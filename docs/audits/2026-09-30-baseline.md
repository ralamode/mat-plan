**P0-1 · 7 of 9 units the log form offers are rejected by the server** (area 3, verified 2026-09-30 by
a vitest probe; introduced by #141)

- `packages/shared/src/strength-session.ts:45`: `unit: z.enum(BODYWEIGHT_UNITS)` (`lb`,`kg`). The
  "Measuring" picker (`strength-form.tsx` ~608/634) offers every `LOGGABLE_UNITS`
  (`lb kg in cm ft m yd sec min`). **Rejected: `in cm ft m yd sec min`.** A timed hold or a distance
  fails zod for the whole session.
- **Rule:** strength-logging guide invariant 4b ("every offerable unit is one the composite FK
  accepts") is true of the DB and false of the write path. DoD: critical flow covered.
- **Fix scope (checked):** `z.enum(LOGGABLE_UNITS)` on the movement unit. The writer already derives
  the dimension from any `Unit` (`writers/strength-session.ts:236-257`), and the CSV export already
  formats time and length (`csv/value.ts`, exhaustive; `sec` → `s`). Add a boundary test per non-mass
  dimension, a `db:verify` round trip for `sec` and `m`, and correct invariant 4b. Known and accepted:
  a non-mass set stays **uneditable** by `editStrengthSetAction` (the writer's edit guard is mass-only,
  `strength-session.ts:412-422`, the same class as the labeled-set debt). Say so in the PR. Keep
  `BODYWEIGHT_UNITS` for the weigh-in form.

**P0-2 · V1-27 still open: doing 2 of 3 scaffolded sets can't be submitted.** It's already filed as

### P1

**P1-1 · The access gate is enforced by the proxy alone, and the proxy is skipped for
prefetch-flagged requests. Only undocumented framework behaviour stops a bypass.** (area 5)

- `apps/web/proxy.ts:97-104`: the matcher has `missing: [next-router-prefetch, purpose: prefetch]`,
  so a request carrying either header **never runs the proxy**. Pages and all six Server Actions have
  no gate check of their own. Only `p/[profileId]/export/route.ts:36` re-checks the cookie.
- **Probe:** `next dev` and a local `next build && next start`, no cookie, route `/p/<uuid>`:
  | Request                                                                                        | Result                                                               |
  | ---------------------------------------------------------------------------------------------- | -------------------------------------------------------------------- |
  | GET or action POST, no header                                                                  | 307 → `/gate`                                                        |
  | GET or action POST with `purpose: prefetch`, `next-router-prefetch: 1`, or `RSC: 1` + prefetch | **400, empty body, before any app code** (nothing in the server log) |
- **So no bypass today, locally.** But the protection is Next's undocumented refusal, not this app.
  Nothing pins it (no test), and Vercel's edge routing was not probed. The repo is public and holds
  two minors' training data.
- **Rule:** SECURITY.md (BOLA-first); AGENTS.md → "page/middleware auth does NOT protect an action".
- **Fix (cheap):** (a) add an e2e or integration assertion that the prefetch-header GET and POST get
  4xx/307 and never 200, so a Next upgrade can't silently open it; (b) defence in depth: re-check the
  gate cookie in the root layout (or a shared `requireGate()` in the DAL that actions call), as the
  export route already does.

**P1-2 · Third-party actions in the prod-DB workflow are tag-pinned.** (area 5)

- `.github/workflows/migrate.yml:37` `pnpm/action-setup@v6` runs in the job whose env holds
  `DATABASE_URL_UNPOOLED` (the **production database credential**, `:50`). A moved or compromised tag
  (tj-actions style) exfiltrates it. The same applies to `gitleaks/gitleaks-action@v3` (`ci.yml:396`)
  with `GITHUB_TOKEN`.
- **Rule:** SECURITY.md → Supply chain. The DX-1 plan already SHA-pins every action in its
  secret-bearing file, so this is an inconsistency.
- **Fix:** SHA-pin with a `# vN` comment every action in `migrate.yml` (and third-party ones in
  `ci.yml`). Dependabot's `github-actions` ecosystem keeps them bumped.

**P1-3 · `audit --prod` never runs in CI**, while AGENTS.md lists it among the CI required checks
("…and `audit --prod` via `pnpm verify`"). (area 6 / seed 5)

- `ci.yml` has no audit step (only comments). #182, a **critical** Next RCE, had to be caught by hand.
- **Fix:** add `pnpm audit --prod --audit-level high` to the `quality` job. It's a config one-liner,
  so plan-exempt, but say so in the PR.

**P1-4 · `docs/status.md` "Where we are" advertises routes that no longer exist.**

- `status.md:10-14` headlines DUALS-1's public `/duals/...` day sheets. The routes and
  `components/duals/` were **removed** (`access-gate.ts:72`: "There is no public path"). This is the
  first line the new SessionStart briefing shows every session.
- **Rule:** status rides with the work (AGENTS.md); #156's lesson.
- **Fix:** rewrite the headline to today's state (V1-24/26/27 in flight, the P0s above, DX
  tooling). Also the stale `program-reference.tsx:29` comment citing `components/duals/day-sheet.tsx` (P2).

**P1-5 · #171's BW warning: the live region mounts with its text, and no `aria-describedby`.**

- `strength-form.tsx:759`: `role="status"` rendered conditionally with its text, which several
  screen readers don't announce, and the `sr-only` BW chip isn't tied to it. (The scaffold message at
  `:314` does it right: the region is always mounted and its content changes.) **Fix:** the same idiom
  as `:314`.
