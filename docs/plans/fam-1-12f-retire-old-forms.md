## The routine after the trim

**Nothing links to the routine page** (`page.tsx:262-265`; `e2e/athletes.spec.ts:123` asserts it): it
is reached by typing its URL. It is still scanned (`e2e/a11y.spec.ts:70-73`), and
`e2e/landing.spec.ts:124-176` replays its Save as a real Server Action. So the trim needs no UX panel,
and the page keeps its `ROUTINE_COPY.orderHeading` region, its buttons and Save.

- **The catalog** becomes `strength` and `life:wrestling_practice`. `strength` stays a member, listed
  nowhere, because `resolveRoutine` never returns an empty routine: with no usable key it returns the
  fallback, and when the fallback is not in the catalog, the whole catalog
  (`packages/shared/src/routine.ts:108-140`). A Life-only catalog would give every athlete with no
  stored routine (`NEUTRAL_DEFAULT_KEYS` is `strength`, `catalog.ts:61`) Wrestling practice: "Life for
  everyone", which D28 rejected.
- **No day page changes.** Today the page shows the routine's Life keys minus Wake
  (`page.tsx:125-127`, `life-section.tsx:17-19`). After the trim it shows the routine's Life keys:

  | Stored `routine_config`                                     | Life on the day page today | After |
  | ----------------------------------------------------------- | -------------------------- | ----- |
  | none (every athlete added in the app)                       | none                       | none  |
  | the full routine (`seed.ts:69-89`; the live household)      | practice                   | same  |
  | Athlete Two's (`seed.ts:92-104`: check-ins, strength, Wake) | none                       | none  |
  | only keys that left (`life:wake`, any `checkin:*`)          | none                       | none  |
  | `life:wrestling_practice` alone                             | practice                   | same  |

  The table covers the seed's shapes and the default. Q5's second read lists the shapes production
  holds, and it gates PR 5.

- **The editor** lists Life items only. What it does not list (`strength`, with its `conditional`
  marker) rides along in the saved order. `savedOrder(initial, listed)` in `lib/routine/catalog.ts`
  builds what Save sends: it splits the carried items from the listed ones by the keys of
  `routineCatalogItems()`, and returns a `RoutineConfig`. When nothing is left it returns
  `buildDefaultRoutine([STRENGTH_KEY])` (`packages/shared/src/routine.ts:79`): `strength` is written as
  the catalog's never-empty member, not as the first-run default. `NEUTRAL_DEFAULT_KEYS` is still never
  written (`catalog.ts:56-59`). So Save is no longer disabled at zero listed items
  (`routine-editor.tsx:144`). One catch: `buildDefaultRoutine` takes keys, so it would drop a carried
  item's `conditional` marker (`routine.ts:79-81`). With items to save, `savedOrder` takes the version
  from `buildDefaultRoutine` and the order from the items themselves.
- **Stored routines are not rewritten.** A key that left is dropped at read, and leaves storage only
  when that athlete's routine is next saved. No schema change (D28).
