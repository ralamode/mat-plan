## Goal

A parent opens a program, puts one or more athletes on it from today or tomorrow, and those athletes'
day pages show it. A parent can take an athlete off, and can see how to undo that. Home names each
athlete's programs, the add-athlete form stops promising a program the household no longer hands out,
and an athlete on no program gets a link to Programs from their day page. Nothing new is stored.

## Risks / rollback

- **The wrong athlete is put on.** The dialog names who is starting. While nothing is logged, a
  same-day Take off removes the start and leaves nothing. Once the athlete has logged, it leaves a
  one-day stretch and the logs stay under that program (C15); the full recovery is to untick the
  day's rows, then Take off. The success line says how to undo a Take off before midnight.
- **A child inherits targets chosen for someone else.** Targets are per program (TGT-1 deferred,
  `fam-1-family-program.md:937`); the dialog says so when someone joins a program that has athletes.
  12d-ii's gate exists because a wrong weight could be stored once anyone can be put on a program.
- **An adult athlete can be put on a program.** Intended: no kind filter in `candidates` or
  `lockAthletes` (`assign.ts:43-60`), and `ID-1` forbids age-based permissions. The day plan reads
  assignments with no kind filter, so they see it.
- **A child can put themselves on a program** from the day page's link. Accepted (`ID-1`: no role
  gate). The safety net is Home's tile, which shows every athlete's programs to whoever opens Home,
  and a same-day Take off.
- **Two parents at once.** The writer locks the program, then the athletes in id order, and skips an
  athlete already on it: one row, both answered ok.
- **Rollback:** each PR reverts on its own. Reverting PR 1 hides the dialog and the button again;
  assignments already made stay valid, because the day page reads them regardless.
