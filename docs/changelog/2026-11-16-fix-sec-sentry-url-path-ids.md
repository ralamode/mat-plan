# Error reports no longer carry an athlete's id or the day in the page address

The Sentry scrubber dropped a request's query string but kept its URL **path**, and the app's routes put public ids and days in the path (`/p/<athlete id>/<yyyy-mm-dd>`, a program's or workout's id). So every error report from an athlete's page carried their id and the day being viewed. C11's review found it on 2026-11-16; it predates C11. `apps/web/lib/sentry-scrub.ts` now masks every UUID as `:id` and every whole `yyyy-mm-dd` segment as `:date` in URL-shaped fields only: the request URL and its `contexts.request` copy, the transaction name, span descriptions, breadcrumb messages, and breadcrumb or span data under `url`, `from`, `to`, `http.url`, `http.target`, `url.full` and `url.path`. The route's shape survives. The deliberate security event (`reportScopeMiss`) keeps its id, because it sits in `contexts.scope_miss`, not a URL field. A test pins that.
