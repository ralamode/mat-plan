# Error reports no longer carry an athlete's id or the day in the page address

The Sentry scrubber dropped `request.query_string`, but the SDK also writes the full address, query included, into `request.url`, `contexts.request.url` and Next's `contexts.nextjs.request_path` (from `captureRequestError`). An athlete's pages put their public id in the path (`/p/<id>`) and the day viewed in the query (`?d=<yyyy-mm-dd>`). So every error report from an athlete's page carried their id and the day. Exception messages could also carry a row's `client_id`. C11's review found it on 2026-11-16; it predates C11.

`apps/web/lib/sentry-scrub.ts` now replaces every UUID in every string it scrubs with `:id`, and cuts the query off the request URL, its `contexts.request` copy and breadcrumb addresses. The one deliberate id, the scope-miss event's `contexts.scope_miss.resource` from `reportScopeMiss`, is restored after the masking. The test fixture is shaped from a real `captureRequestError` event, and tests pin both the masking and the exemption.
