# `pnpm typecheck` now checks `packages/shared`, its tests included

`packages/shared` had no `tsconfig.json`. Its source was type-checked only through the files the app and `packages/db` import, and its `*.test.ts` files were checked by nothing, because no project imports a test file and vitest strips types without checking them. So every type-level proof in a shared test, such as the `satisfies` checks in `program/shapes.test.ts`, was inert. A probe showed it: a type-error expectation added to a shared test left `pnpm typecheck` at exit 0, and the same line in a web test failed with TS2578.

The package now has its own `tsconfig.json` (mirroring `packages/db`'s), a `typecheck` script, and `typescript`, `vitest` and `@types/node` as dev dependencies at the versions the workspace already uses. The root `typecheck`, and so the pre-push hook, `pnpm verify` and CI's `quality` job, runs it. The first run found one error, a `Set` inferred too narrowly in `movement-picker-catalog.test.ts`, now fixed. `packages/engine` still has no project of its own; its source has no tests.
