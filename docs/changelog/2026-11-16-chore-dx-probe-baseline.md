# `pnpm probe` refuses to report a catch when the check was already failing

`pnpm probe` now runs the gate once before mutating anything, and the gate must pass. Before, a test that was already failing could print the `--expect` text on its own, for example its name in the failure output, so the probe reported "RED for the named reason" when the mutation had done nothing. A lane hit exactly that on 2026-11-16. A failing baseline is now reported as DID-NOT-PROVE, with its last 20 lines shown, and the file is never mutated. So is a passing baseline whose output already contains the `--expect` text, since a failure could not then be pinned on that assertion. It costs one extra run of the gate. There's a new self-test in `probe.test.sh`, and the review-pr skill and the lessons entry describe the four outcomes.
