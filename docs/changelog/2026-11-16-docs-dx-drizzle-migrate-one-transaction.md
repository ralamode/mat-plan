# The docs now say drizzle runs all pending migrations in one transaction

AGENTS.md, `.squawk.toml` and the db-migration skill said drizzle's migrator wraps each migration file in its own transaction. It doesn't: drizzle-orm 0.45.4's `migrate()` (`pg-core/dialect.js`) opens one transaction and runs every pending file inside it. This was first recorded in `docs/tech-debt.md` on 2026-10-09 (TEN-2a), and that entry's proposed fix was never made. Native Scaling found it again while building SCALE-3, and the board confirmed it from the source. The tech-debt entry is now closed. Two consequences are now written down. `CREATE INDEX CONCURRENTLY` can't run through the migrator at all. And keeping a `NOT VALID` and its `VALIDATE` apart depends on the one-unapplied-migration-at-a-time queue, not on putting them in separate files. AGENTS.md now states the queue as a rule: `migrate.yml` keeps only one pending run and drops older pending ones, so two quick merges would apply together in one transaction. Nothing applied so far is affected: every production run has applied at most one migration, except the very first deploy, which applied 0000 and 0001 together on an empty database.
